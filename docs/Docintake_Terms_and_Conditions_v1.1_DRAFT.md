## 10. Document Submission and Processing

**10.1 Document Standards & Accepted Formats.** The Platform accepts digital document submissions in PDF format and approved raster formats (PNG, JPEG, TIFF). Documents must be clear, genuine, unaltered, uncorrupted, and legible. The Platform enforces strict file-content validation (verifying true MIME types by magic bytes, not file extensions) and will reject structurally invalid, corrupted, or unsupported files.

**10.2 Antivirus & Security Screening.** All uploaded files undergo automated ClamAV antivirus scanning and PDF active-content structural inspection. Files containing malware, embedded launch actions, suspicious scripts, or synthetic vector manipulation are rejected immediately.

**10.3 Document Expiration Policy & Automatic Purge.** All submitted identity documents, passports, and driving licences must be valid and unexpired at the date of application submission. Documents displaying an expired validity period will fail automated validation checks. Upon detection of an expired document, the User or Guardian will be notified, and any existing expired document binary or database record from that session will be purged from the system.

**10.4 On-Premise Storage & Encryption.** All documents submitted through the Platform reside strictly within Docintake's On-Premise Infrastructure. Document binaries are stored in MinIO object storage utilizing server-side encryption (SSE-S3 / SSE-KMS) and audit-standardized naming (`<name>_<idnumber>_<date>.<ext>`). Structured records are maintained in PostgreSQL. **No document content is transmitted to any external public cloud storage or third-party cloud API.**

**10.5 AI-Assisted Extraction & User Verification.** Document data extraction is performed locally using on-premise vision-language models (Qwen2.5-VL running via Ollama). Automated extraction is an algorithmic tool and does not guarantee error-free results. Users and Guardians are provided an in-app verification interface to review, mask/unmask, and confirm all extracted fields prior to final submission.

**10.6 Automated Cross-Validation & Business Rules.** Submitted data is evaluated against deterministic validation rules, including mandatory field presence, date consistency (issue date preceding expiry date), and applicant name matching. For Premium / Cross Border applications, cross-document comparison is automatically conducted between National ID and Passport fields (validating name tokens, DOB, and nationality).

**10.7 Human Review Procedures.** Applications encountering edge-case discrepancies, unreadable image zones, or confidence scores requiring clarification are routed to an authorized Human Review queue. Human review is conducted strictly under role-based access control and supervisory audit logging.

**10.8 Idempotency & Clean Up.** The Platform prevents duplicate document submissions through content hashing (SHA-256). Interrupted or incomplete uploads are cleaned up automatically.
